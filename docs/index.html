Your coding agent
doesn't need your keys.

It only needs their names. hivelock keeps the values on your machine — encrypted, injected only when a command actually runs.

what leaves your machine

without

One paste, three copies you didn't intend.

with hivelock

The name is all the agent ever holds.

where it sits

Your message

Secret detected, stored, message held back — masked text handed straight back to you.

Commands

The agent writes {{lock:NAME}}. The real value appears only inside that one command.

Tool output

Known values masked, new ones captured — before the model reads a line.

Old sessions

Transcripts already on disk are scrubbed in place.

per secret

open

Agents use it freely. Value never leaves the command that needs it.

ask

Every single use waits for your approval, in the agent's own prompt.

locked

Passphrase, human only. Agent shells have no terminal, so they can't answer it.

honest limits

  • Pasted secrets never reach the provider
  • Values live encrypted, readable only by you
  • Output masked, encodings included
  • Old transcripts scrubbed
  • Locked secrets need a human at a terminal
  • Not a sandbox: anything running as you can read the key
  • A command given a secret can still leak it, transformed
  • Masking can confirm a guess
  • Values under 8 characters aren't masked
  • @file attachments skip hooks; scrubbed after

day to day

# move what you already have
hivelock import .env
hivelock import ~/.ssh/deploy_key

# the agent writes names; you never paste a value again
curl -H "Authorization: Bearer {{lock:GITHUB_TOKEN}}" api.github.com/user

# tighten a secret, or check everything still works
hivelock lock PROD_DB_PASSWORD
hivelock doctor
